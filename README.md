# Wayfarer

A client-side outing companion prototype built with React, TypeScript, and Vite, with a small Node.js server for nearby-place searches and an optional, user-triggered ElevenLabs speech proxy. There is no account, hosted diary model, analytics, external font, or database. Diary generation and conversation responses run locally; optional speech recognition may use the browser's transcription service, and requested TTS text goes to ElevenLabs. Place discovery is an explicit exception to fully local operation: after the user chooses GPS, manually selected map-point, or typed-area search, approximate coordinates and interest terms are sent to the application server, which constructs a fixed-scope query to OpenStreetMap Overpass. Typed-area search also sends the entered area text directly to OpenStreetMap Nominatim to resolve an approximate centre.

## Run locally

```sh
npm install
npm run dev
```

To run the focused tests, run `npm test`. To make a production build, run `npm run build`.

### Production deployment

The repository has no preconfigured deployment target or serverless-host configuration. Nearby search needs the same-origin `/api/nearby` endpoint as well as the static app; deploying only the Vite output to a static host (including `vite preview`) will not provide that endpoint.

The included Node.js production server is the smallest supported deployment path. Use a Node.js 20+ host with outbound HTTPS access to the allowlisted OpenStreetMap Overpass services, deploy the repository including the built `dist/` directory, and run:

```sh
npm run build
npm start
```

The server listens on `0.0.0.0` and uses the platform-provided `PORT` environment variable, or port 3000 when unset. Set `HOST` only if the deployment environment requires a different bind address. Vite development uses the same endpoint handler through middleware; Vite preview is only a static preview and is not the production server.

### Overpass client identification

Nearby search identifies itself with `Wayfarer/1.0 (+https://github.com/moisturizedpotato/Adventure-Companion)`. To use another truthful identifier, set `OVERPASS_USER_AGENT` in the environment of the Node.js server (including the Vite process during local development); include the real project URL or contact information and do not use fabricated details. Keep this configuration on the server and restart the process after changing it.

If the override is invalid, nearby search returns a clear `configuration_required` error without contacting an Overpass instance. The same actionable error is returned if an instance indicates that the configured identification needs attention. Search can still continue through the app's saved/manual-place fallback.

## What works

- Onboarding saves the user's name, interests, outing preferences, and optional area in browser `localStorage`.
- An outing suggestion requires a search area, timing, available hours, interests, and either a place the user manually added and confirmed or a named OpenStreetMap result they choose after an explicit nearby search. Saved places can be selected directly, without a live nearby result. If a live search fails, the app reports it as unavailable; a plan made from a saved/manual place continues to identify that fallback. GPS searches use the device's current position; typed-area searches geocode the locality the user entered; manual map-point search accepts coordinates or a copied OpenStreetMap Share link. Typed-area and manual map-point searches do not request device location. Nearby searches cover 3 km around the selected point. Coordinates are rounded to about 100 m before being sent to the application server and are not saved by this app. Search categories are selected and ranked around the user's interests, including adventure activities; users can request another search with a more specific activity such as kayaking or climbing. OpenStreetMap place names, relevant tags, and record links are surfaced with attribution. The application server sends requests sequentially to a fixed allowlist of Overpass instances, with bounded timeouts/retries and clear errors if the service is unavailable. Map data may be incomplete or stale: the app does not verify visitor access, opening times, routes, or safety.
- Friend preferences can be added without an account and are included when ranking saved places and explaining a suggestion.
- Typed session notes and user-kept moments are saved locally as the outing proceeds. Users can attach a resized image to a diary entry; it is stored in browser local storage with that entry. Image understanding is optional and requires a separate, explicit opt-in when writing the entry. If chosen, a local vision model describes visible details and Gemma can use those details in the diary; neither model uploads the image.
- Diary entries can be composed by the local fallback or generated with Gemma 2 2B in the browser. Gemma is optional: the user must accept its terms and download its model/runtime assets (about 1.49 GB of model files, plus runtime assets). It requires WebGPU with `shader-f16` and approximately 1.9 GB of GPU memory. The prompt contains extracted, compact fact cues rather than the user's original sentences and asks Gemma to create a reflective entry without a fixed structure. Photo analysis requires a separate 2.77 GB Phi-3.5 Vision model download and approximately 3.95 GB of GPU memory; the app swaps models sequentially to avoid keeping both loaded together. Image observations are limited to visible details. Generation and fallback preview are both saved as the diary entry. If Gemma is unavailable, the clearly labelled local composition fallback remains usable. Reading, exporting, and deleting local diary data are available.
- During an outing, users can explicitly start a continuous voice conversation with local Gemma, or type messages. Browser speech recognition is used only after the user accepts the disclosure and grants microphone permission; browser vendors may send captured audio to their transcription service. Recognized user speech is kept with local outing notes; Gemma replies locally. When voice chat is active, reply text is sent to the application's server and ElevenLabs returns audio. Diary entries can also be read aloud on demand. ElevenLabs receives only text the user asks to speak and the selected voice ID; the API key remains server-side. The configured voice uses a slower, expressive setting for a narrative, friendly delivery.

## Privacy and model boundaries

The app stores profile data, saved places, draft session notes, diary entries, and attached diary photos in this browser's `localStorage`. This app does **not encrypt** that data. Browser profile access and site-data clearing affect its availability. Photos are resized before storage and remain on this device; when the user explicitly opts in to photo analysis, the image is processed locally by Phi-3.5 Vision and only a short visible-detail description is passed to Gemma. Images and descriptions are not uploaded. JSON export and delete-all controls are in Settings.

Nothing is sent for place discovery until the user taps a search button. GPS search requests browser permission. GPS and manual map-point searches send coordinates rounded to about 100 m, along with interest/refinement text, to this application's nearby-search server. Typed-area search sends the entered place text directly to `nominatim.openstreetmap.org` to resolve an approximate centre, then sends rounded coordinates and interest/refinement text to the application server. The application server constructs the fixed 3 km Overpass query and sequentially sends it to a fixed allowlist of public Overpass instances. The server necessarily receives the location query and can observe ordinary request metadata; the server code does not persist search coordinates or log request bodies. The Overpass service that answers receives the query and the application server's network metadata. The hosting provider may have its own infrastructure logging/retention policies, which this application does not control. Search results are shown with source links and `© OpenStreetMap contributors` attribution; the data is available under the [Open Database License](https://www.openstreetmap.org/copyright). Coordinates are not persisted in browser storage or diary entries. Nearby search requires internet access and a deployment that runs the included Node.js API server; it does not work offline. Users who do not wish to share location or area text can add a place they have personally confirmed.

Gemma 2 2B is an optional local language model. Before setup, the app checks secure context, WebGPU, and `shader-f16`; actual inference additionally depends on GPU memory and browser/runtime compatibility. Initial setup downloads roughly 1.49 GB of model files from Hugging Face plus the compiled runtime from a version-pinned jsDelivr URL, and requires accepting the [Gemma Terms of Use](https://ai.google.dev/gemma/terms). Those hosts receive ordinary network metadata during setup; after setup, diary prompts and generation run locally and diary content is not sent to an inference service. Optional photo analysis downloads Phi-3.5 Vision (about 2.77 GB) and its runtime on the first opt-in. It requires around 3.95 GB of GPU memory, and the app unloads Gemma while the vision model runs, then reloads Gemma to compose the entry. The photo remains local. Model files are cached in browser storage and may be evicted; the Settings control removes both model caches. On unsupported devices, the local composition fallback remains available. Diary generation uses compact fact cues and sampling to encourage fresh prose without a fixed template; model weights are not fine-tuned.

Speech features are opt-in. Starting voice chat activates browser speech recognition and may send microphone audio to a browser vendor's transcription service; microphone access is not requested before the user starts. Recognized text is added to local outing notes and sent to Gemma on-device. With voice chat active, the reply text is sent through the application's server to ElevenLabs for TTS. Choosing “Read the diary out” sends that diary text to ElevenLabs. The app server does not log speech request bodies, and the ElevenLabs API key never reaches the browser. Review ElevenLabs' current data-handling and retention terms before enabling the integration. The microphone stops when voice chat is stopped, paused, or the outing screen closes. Photo analysis uses the optional local Phi-3.5 Vision model only after a separate user opt-in.

To configure ElevenLabs, copy `.env.example` to `.env`, set `ELEVENLABS_API_KEY` and `ELEVENLABS_VOICE_ID` using a voice available to your account, then restart `npm run dev` or `npm start`. The voice ID is selectable because voice-library access varies by account. Do not commit `.env`. The API server limits speech generation to 30 requests per IP address per hour and accepts text up to 5,000 characters. Without both settings, voice chat can still display Gemma replies as text and read-aloud stays disabled. Voice chat also requires Gemma to be set up and loaded in Settings. The server scripts read `.env` with Node.js 20.12 or newer.

The camera requires a browser that exposes `getUserMedia`, normally on HTTPS or `localhost`, and an explicit user permission. The stream is shown only in the current page, stops when the outing ends, and can be paused or stopped at any time. Captured or selected images are not saved unless the user chooses to attach one to the diary. Attached images are resized and stored with the entry in local browser storage. If the user separately opts into image analysis, the attached image is analyzed on-device by Phi-3.5 Vision; otherwise it is not provided to an AI model.

The layout and web APIs target modern browsers. The app was built and smoke-tested in the integrated Chromium browser; speech recognition is available only in browsers exposing `SpeechRecognition` or `webkitSpeechRecognition`. Other browsers may differ in camera, service-worker, geolocation, and speech behavior. Geolocation requires a secure context (HTTPS or localhost) and explicit browser permission. The Settings screen reports detectable capabilities. Offline startup and local diaries work after the service worker has cached the app shell; nearby search and ElevenLabs speech require a network connection.
